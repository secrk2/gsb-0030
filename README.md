# 序流 XULIU · 持续集成系统

为研发团队提供**流水线编排**与**运行仪表盘**，替代上线时的人肉串流程。

- **DAG 编排**：阶段间支持串行、并行分支、失败中止 / 继续；保存时做环形依赖校验，命中环会被拦截并返回具体环路径，画布上同步高亮。
- **真拖拽连线**：从阶段节点右侧圆点直接拖到下游节点建立依赖（不是下拉选依赖），点击连线即可删除。
- **阶段模型**：5 种类型（构建 / 单测 / 镜像 / 部署 / 人工卡点）、超时时间、失败策略（中止 / 继续）。
- **仪表盘**：今日运行次数、成功率、平均时长、近 7 天趋势，以及**卡在人工卡点超过 N 小时的红灯**（N 可调，默认 4 小时）。
- **三端布局**：左侧流水线列表 / 中间 DAG 画布 / 右侧阶段属性与执行记录。
- 零运行时依赖（Node 内置 http），数据落在 JSON 文件，docker compose 一键拉起。

## 快速开始

### 方式一：docker compose（推荐）

```bash
docker compose up -d --build
# 打开 http://localhost:8130
```

数据持久化在命名卷 `xuliu-data` 中；首次启动若库为空会自动播种初始数据。
重置为出厂数据：`docker compose down -v && docker compose up -d --build`。

### 方式二：本机 Node（≥ 20）

```bash
node server/seed.js --force   # 写入初始数据（可选，首次启动会自动播种）
node server/index.js          # 默认 8130
```

环境变量：

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `8130` | 服务端口 |
| `GATE_RED_HOURS` | `4` | 人工卡点红灯阈值（小时），页面上也可临时调整 |
| `DATA_DIR` | `./data` | JSON 数据文件目录 |

## 初始数据

- **3 条流水线**，各 7 个阶段，覆盖串行、并行分支与人工卡点：
  - 后端服务发布（构建 → 单测/集成测试并行 → 镜像 → 预发 → 生产审批 → 生产）
  - 前端站点发布（构建 → 单测/E2E 并行 → 镜像 → 上线审批 → 生产节点/CDN 刷新并行）
  - 基础设施变更（Plan → 合规/安全扫描并行 → AMI → 变更审批 → 灰度 → 全量）
- **23 条执行记录**：含成功、失败（含失败继续策略）、运行中、等待审批；
  其中 3 个等待中的人工卡点（1.0h / 6.2h / 25.5h），默认阈值下后两个亮红灯。
- 今日固定有 6 次运行，保证仪表盘 KPI 开箱即有数据。

## 操作指南（编排页）

1. 左侧选择流水线（或「＋ 新建」）。
2. 中间画布：
   - **拖节点本体** = 移动位置；
   - **按住节点右侧圆点拖到另一个节点** = 建立「本节点 → 目标节点」的依赖；
   - **点击连线** = 删除该依赖；
   - 「自动排版」按依赖层级重新排列。
3. 右侧属性面板编辑名称 / 类型 / 超时 / 失败策略，也可在「前置依赖」标签上点 × 移除。
4. 「保存编排」时服务端再次做 DAG 校验；若有环，顶部红色横幅与画布脉冲红会标出那条环，例如
   `Maven 构建 → 单元测试 → 构建镜像 → Maven 构建`，删掉环上任意一条连线即可保存。
5. 「▶ 触发运行」产生一次执行（模拟引擎），含卡点的流水线会停在第一个卡点；
   在右侧「执行记录」里点开等待中的记录，可**审批通过 / 驳回**（驳回即中止，下游全部跳过）。

## HTTP API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/meta` | 阶段类型、失败策略、红灯阈值等常量 |
| GET/POST | `/api/pipelines` | 列表 / 新建（DAG 校验） |
| GET/PUT/DELETE | `/api/pipelines/:id` | 详情 / 更新（DAG 校验）/ 删除 |
| POST | `/api/pipelines/:id/trigger` | 触发执行 |
| GET | `/api/runs?pipelineId=&status=&limit=` | 执行记录 |
| POST | `/api/runs/:id/approve` | 人工卡点 `{"decision":"approve|reject","operator":"...","comment":"..."}` |
| GET | `/api/stats/overview?gateHours=4` | 仪表盘 KPI、7 天趋势、卡点红灯 |

环形依赖的错误响应：

```json
{
  "error": "检测到环形依赖，已被拦截：A → B → C → A。请删除环上的任意一条连线后再保存。",
  "details": { "code": "CYCLE", "cycle": ["a", "b", "c", "a"], "cycleNames": ["A", "B", "C", "A"] }
}
```

## 设计说明

- **环检测**：三色 DFS（white/gray/black），遇到指向 gray 节点的回边时沿递归栈切片，还原出首尾闭合的环；新建、更新、自环、悬空引用分别在校验阶段给出明确错误。前端连线时做同款实时检测，保存时服务端二次兜底。
- **执行语义**：`deps` 表示前置依赖，边方向为前置 → 当前；同层（最长依赖链深度相同）即为可并行分支；阶段失败按其失败策略决定下游是中止（skipped）还是继续。
- **可视化**：阶段类型色取自经验证的分类色板，类型同时用图标 + 文字标签 + 卡点虚线描边做次级编码，不依赖颜色 alone；状态色（成功绿 / 失败红 / 等待黄）与分类色分离；支持深色模式。
